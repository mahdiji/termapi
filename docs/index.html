TUI API Client · Local-first

TermAPI,
API client di terminal.

TermAPI adalah klien API berbasis terminal yang dibangun dengan Go dan Charmbracelet Bubble Tea. Kelola collection sebagai YAML, simpan environment dan history secara lokal, bandingkan response antar-run, jalankan batch, serta inspeksi WebSocket dan gRPC — tanpa meninggalkan terminal.

01 · MULAI

Ringkasan#

TermAPI adalah aplikasi TUI (terminal user interface) untuk mengirim dan memeriksa request HTTP, memantau koneksi WebSocket/gRPC, menjalankan kumpulan request, dan menyimpan riwayat response. Semua data proyek disimpan di dalam folder proyek Anda:

$

Terminal-native

Keyboard-first, mouse-friendly, dan tetap ringan. Cocok untuk sesi SSH, container, atau mesin tanpa GUI.

Y

Collections sebagai YAML

Request dapat dibaca, di-diff, dan di-commit seperti source code. Tidak ada format biner atau database tersembunyi.

DB

History di SQLite

Setiap eksekusi disimpan lokal bersama variabel yang ditangkap dari response JSON.

Δ

Diff response

Bandingkan baseline vs response terbaru dari request yang sama, atau pilih baseline lain secara manual.

Cocok untuk Debugging API, verifikasi setelah deploy, eksplorasi endpoint, uji alur login → ambil token → panggil endpoint, serta monitoring WebSocket/gRPC sederhana.

Bukan apa

  • Bukan aplikasi web atau layanan cloud; tidak ada akun, sinkronisasi, atau telemetry.
  • Bukan pengganti penuh Postman/Insomnia untuk scripting, mock server terkelola, atau kolaborasi tim.
  • Bukan HTTP/2 atau HTTP/3 client dengan pengaturan penuh; fokusnya alur kerja terminal yang cepat.

Instalasi & build#

Kebutuhan

KebutuhanKeterangan
Gogo 1.27.1 sesuai go.mod. Disarankan versi yang sama atau lebih baru.
CGO + compiler CDibutuhkan github.com/mattn/go-sqlite3. Di Linux: gcc/build-essential. Pastikan CGO_ENABLED=1.
TerminalMinimal 105 × 32 sel. Layar lebih kecil akan menampilkan peringatan. Wire inspector minimal 70 × 20.

Izin filesystemAplikasi menulis collections/ dan .termapi/ di root proyek.

Build binary

Jalankan dari root proyek (folder yang berisi go.mod):

cd TermAPI
go mod download
CGO_ENABLED=1 go build -o termapi ./cmd/termapi
./termapi

Alternatif tanpa menghasilkan binary permanen:

go run ./cmd/termapi
Penting: lokasi kerja TermAPI mencari folder proyek dengan menelusuri ke atas sampai menemukan go.mod. Jika dijalankan di luar proyek Go, folder kerja saat ini dianggap root. History, environment, dan konfigurasi selalu mengarah ke root tersebut, sedangkan collections dapat dioverride dengan TERMAPI_COLLECTIONS_DIR.

Build komponen pendukung

# Mock server WebSocket + gRPC untuk uji Wire Inspector
CGO_ENABLED=1 go build -o mockserver ./cmd/mockserver
./mockserver

# Demo Wire Inspector saja
go run ./cmd/wirescreen-demo ws://localhost:8080/ws

# Echo server WebSocket sederhana
go run ./server3

Verifikasi

go vet ./...
go test ./...

Mulai cepat#

Buka aplikasiJalankan ./termapi dari root proyek.
Buat requestCtrl+N, pilih New Request, tentukan nama, folder, dan method.
Isi URLKetik URL di bar, atau pilih request yang sudah ada dari sidebar.
KirimEnter di URL bar atau klik tombol Send.
SimpanCtrl+S untuk menyimpan ke collection YAML.
BandingkanJalankan lagi setelah deploy, lalu Ctrl+D untuk membuka Diff Viewer.

Contoh: request pertama

  1. Tekan Ctrl+N. Pada layar NEW REQUEST, isi nama misalnya List users.
  2. Pilih folder tujuan (atau buat collection baru dengan Ctrl+T lalu ganti tipe ke folder).
  3. Pilih method dengan ←/→, lalu Enter.
  4. Ketik https://api.example.com/users di URL bar dan tekan Enter.
  5. Response muncul di panel bawah. Gunakan Tab untuk masuk ke panel response, lalu Tab lagi untuk berpindah Body/Cookies/Headers.
  6. Ctrl+S untuk menyimpan. Folder yang belum ada akan dibuat otomatis.

Jika memakai auth atau cookie

Request dengan header sensitif, cookie, auth, atau query sensitif akan diblokir sampai origin-nya masuk allowlist. Tambahkan lewat Ctrl+G; formatnya adalah string multi-baris berisi satu origin per baris:

scope: |
  https://api.example.com
  http://localhost:8080

Lihat Global Scope untuk aturan validasi lengkap.

Collections & YAML#

Setiap subfolder langsung di dalam collections/ adalah sebuah collection. Subfolder di dalamnya menjadi grup request. File _folder.yaml menyimpan metadata folder; request disimpan sebagai file .yaml biasa.

collections/
├── users/
│   ├── _folder.yaml
│   ├── list-users.yaml
│   ├── get-user.yaml
│   └── admin/                 # subfolder = grup request
│       ├── _folder.yaml
│       └── disable-user.yaml
└── auth/
    ├── _folder.yaml
    └── login.yaml

.termapi/
├── global.yaml                # scope + response_ratio
├── envs/
│   └── staging.yaml
├── history.db                 # SQLite
└── trash/                     # item terhapus (bisa dipulihkan manual)

Metadata folder

id: users
name: Users
type: collection      # collection | folder

Field request

FieldTipeKeterangan
idstringID unik. Jika kosong, dibuat dari nama file (slug).
namestringNama tampilan. Jika kosong, memakai nama file.
methodstringDefault GET.
urlstringURL request, boleh memakai {{VARIABLE}}.
params_list[]KVRowQuery dan path parameter.
headers_list[]KVRowHeader request.
body_specBodySpecBody terstruktur (raw/fields/file).
authAuthSpecKonfigurasi autentikasi.
cookies[]KVRowCookie yang digabung ke header Cookie.
paramsstringLegacy. Dinormalisasi ke params_list.
headersmapLegacy. Dinormalisasi ke headers_list.
bodystringLegacy. Dinormalisasi ke body_spec.

KVRow

- key: Authorization
  value: "Bearer {{token}}"
  description: ""          # opsional
  kind: text               # text | file (khusus multipart)
  disabled: false          # true = baris dilewati

BodySpec

body_spec:
  type: json               # none|json|xml|text|form|multipart|binary|graphql
  raw: |
    {
      "name": "Ada"
    }
  content_type: ""         # opsional, override Content-Type
  fields: []               # dipakai form/multipart
  file: ""                 # dipakai binary

AuthSpec

auth:
  type: bearer             # none|bearer|basic|api_key
  token: "{{token}}"
  # basic:
  username: ""
  password: ""
  # api_key:
  key: X-Api-Key
  value: "{{api_key}}"
  add_to: header           # header|query

Contoh lengkap

id: create-user
name: Create user
method: POST
url: "{{BASE_URL}}/users"
headers_list:
  - key: Accept
    value: application/json
  - key: Content-Type
    value: application/json
params_list:
  - key: notify
    value: "true"
body_spec:
  type: json
  raw: |
    {
      "name": "Ada Lovelace",
      "email": "ada@example.com"
    }
auth:
  type: bearer
  token: "{{token}}"
cookies:
  - key: session
    value: "{{session_id}}"

Perilaku penyimpanan

  • Nama file dibuat dari slug nama (huruf kecil, non-alfanumerik menjadi -). Duplikat mendapat suffix -2, -3, dan seterusnya.
  • Penulisan memakai file sementara lalu rename, sehingga file tidak setengah tertulis jika proses berhenti.
  • Hanya file .yaml yang dimuat. File/folder berawalan titik diabaikan.
  • Menghapus item memindahkannya ke .termapi/trash/<timestamp>-<nama>, bukan menghapus permanen.
  • Path tidak boleh keluar dari direktori collections (dicek dengan path relatif).
  • Collection root dapat diganti dengan environment variable TERMAPI_COLLECTIONS_DIR.
Versioning Karena collection berupa YAML, Anda bisa melakukan review perubahan request lewat Git, sama seperti kode. Jangan commit secret; gunakan environment variable dan file env yang tidak di-commit.

Variabel & template#

Gunakan sintaks {{NAMA_VARIABEL}} di URL, params, headers, cookies, body, dan auth. Penggantian dilakukan tepat sebelum request dikirim.

GET {{BASE_URL}}/users/{{user_id}}
Authorization: Bearer {{token}}

{
  "email": "{{email}}"
}

Sumber variabel dan prioritas

PrioritasSumberUmurLokasi
1 (tertinggi)Session variablesSelama proses berjalanMemori; diisi dari response JSON
2Environment aktifPersisten.termapi/envs/<nama>.yaml
3Nilai literalPersistenFile request YAML

Session variables menimpa environment. Environment aktif hanya satu per waktu; pilih lewat Ctrl+E.

Variabel yang ditangkap otomatis

Setelah response sukses (status 2xx/3xx), TermAPI mem-flatten JSON scalar menjadi variabel dengan path titik dan indeks array:

{
  "token": "eyJ...",
  "user": { "id": 7, "role": "admin" },
  "items": [ { "sku": "A-1" } ]
}

Menghasilkan variabel:

token       = eyJ...
user.id     = 7
user.role   = admin
items[0].sku = A-1
  • Hanya nilai string, angka, dan boolean yang disimpan. null, object, dan array kosong dilewati.
  • Maksimal 1.000 variabel dan kedalaman 32 level per response.
  • Variabel ini masuk ke session variables, sehingga langsung bisa dipakai request berikutnya pada proses yang sama.
  • Pada batch chaining, variabel juga disimpan per-batch dan diterapkan ke request selanjutnya sebelum dikirim.

Perlakuan khusus token

Jika session variable bernama token tersedia (misalnya dari response login), TermAPI:

  • Mengganti pola Bearer token / bearer token pada header dengan Bearer <nilai token>.
  • Jika auth diset none dan belum ada header Authorization, menambahkan Authorization: Bearer <token> secara otomatis.
Keamanan Environment dan collection disimpan sebagai teks biasa. Jangan menyimpan token produksi permanen di file yang di-commit. Manfaatkan session variables atau environment lokal yang di-ignore.

Request editor#

Method & URL

Method yang didukung: GET, POST, PUT, DELETE, PATCH, OPTIONS, HEAD. Warna pill mengikuti semantik method.

  • Jika URL tidak memiliki skema, localhost/127.0.0.1/[::1] memakai http://; host lain memakai https://.
  • Query string yang diketik di URL otomatis dipindahkan ke tabel Params saat fokus berpindah, agar tidak terkirim ganda.
  • Path parameter didukung dengan {key} atau segmen :key. Nilainya diambil dari baris Params dengan key yang sama.
  • Baris Params yang tidak terpakai sebagai path parameter akan ditambahkan sebagai query string.

Tabel key/value

Berlaku untuk Params, Headers, Cookies, form body, dan multipart:

Mode raw Params memakai format key=value per baris; Headers memakai Nama: nilai. Baris berawalan # dianggap nonaktif.

  • F6 prettify JSON, F7 minify JSON, F8 validasi JSON/XML.
  • Untuk multipart, tekan t pada baris untuk mengubah tipe menjadi file, lalu isi path file pada kolom value.
  • Body tidak dikirim untuk GET dan HEAD, sesuai perilaku HTTP client.
  • Content-Type hanya diisi otomatis jika header tersebut belum ada.

Auth

Cookies

Baris cookies digabung menjadi header Cookie dan digabungkan dengan header Cookie manual bila ada. TermAPI juga memakai cookie jar sesi, sehingga Set-Cookie dari response otomatis tersedia untuk request berikutnya selama proses berjalan.

Response viewer#

Panel response menampilkan status, waktu, ukuran, dan isi response. Semua konten berada dalam satu frame agar sejajar dengan editor request.

Tab

  • Body — body response.
  • Cookies — cookie dari response.
  • Headers — header response yang sudah diurutkan.

Mode tampilan

ModeIsi
PrettyJSON diindentasi 2 spasi. Filter gjson diterapkan pada mode ini.
RawBody asli tanpa prettify. Error ditampilkan dalam bentuk teknis.
PreviewRingkasan metadata: method, URL, status, Content-Type, ukuran, waktu, timing DNS/connect/TLS/first byte/total, redirect, dan info TLS.

Filter gjson

Klik field gjson di toolbar atau tekan / saat fokus tidak berada di input/editor. Contoh ekspresi:

.data
.data.items.0.name
.data.items.#(status=="active").id

Filter hanya berlaku jika body valid JSON dan ekspresi menghasilkan nilai. Object/array ditampilkan sebagai JSON; scalar ditampilkan sebagai string. Jika tidak ada hasil, body asli yang ditampilkan.

Pencarian teks dan seleksi

  • Ctrl+F membuka pencarian teks pada tab/mode aktif.
  • n / N ke match berikutnya/sebelumnya; match aktif disorot lebih terang.
  • Klik lalu drag untuk memilih baris; y atau Enter menyalin seleksi. Jika tidak ada seleksi, seluruh tab disalin.
  • Ctrl+Y menyalin seluruh tab dari mana saja.
  • Esc membersihkan seleksi/fokus response; jika request masih berjalan, Esc membatalkannya.

Batas dan perilaku jaringan

AspekNilai

10 · DASAR

Keamanan & Scope#

TermAPI memakai model allowlist origin. Request yang membawa kredensial hanya boleh dikirim ke origin yang secara eksplisit diizinkan.

Kapan Scope diperlukan?

Scope dicek jika salah satu kondisi berikut terpenuhi:

  • Ada header sensitif: nama mengandung auth, cookie, token, secret, password, credential, session, apikey, atau berakhiran key.
  • Ada query parameter sensitif dengan pola nama serupa.
  • Ada cookie yang aktif.
  • Auth bukan none.

Jika diperlukan tetapi origin tidak ada di allowlist, request dihentikan dengan pesan credentials blocked: add the exact request origin to .termapi/global.yaml.

Format origin

Satu origin per baris: scheme://host[:port]. Path harus kosong atau /. Tidak boleh ada userinfo, query, atau fragment.

https://api.example.com
https://api.example.com:8443
http://localhost:8080
http://127.0.0.1:3000
  • Hanya http dan https.
  • Port default dinormalisasi: https://host:443 sama dengan https://host.
  • Host case-insensitive.
  • Wildcard (*.example.com) tidak didukung; daftarkan origin persis.
  • Redirect ke origin di luar allowlist akan diblokir jika request memakai kredensial.

Penilaian risiko di layar Scope

Layar Global Scope mengklasifikasikan origin: LOCAL (localhost/loopback), LAN (private/link-local/.local/.internal), atau PUBLIC. Risiko LOW untuk HTTPS, MEDIUM untuk HTTP lokal/LAN, HIGH untuk HTTP publik.

Secret tidak dienkripsi Environment YAML, request YAML, dan history SQLite disimpan sebagai teks biasa. Lindungi direktori proyek dan jangan commit file yang memuat token/kredensial.

History#

Setiap request yang selesai (termasuk yang gagal) disimpan ke .termapi/history.db. History menjadi sumber data untuk Diff Viewer dan untuk menelusuri kembali response lama.

  • Ctrl+O membuka layar History.
  • ↑/↓ atau j/k memilih run; PgUp/PgDn per halaman.
  • Ctrl+F mencari berdasarkan request, URL, method, status, atau collection.
  • Ctrl+D menghapus run terpilih (hanya di layar History).
  • Tab berpindah tab response (Body/Cookies/Headers) pada panel bawah.
  • Esc kembali ke editor.

Skema database

collections (
  id INTEGER PRIMARY KEY,
  name TEXT NOT NULL,
  folder_path TEXT NOT NULL UNIQUE,
  base_url TEXT NOT NULL DEFAULT ''
)

history_runs (
  id INTEGER PRIMARY KEY,
  collection_id INTEGER REFERENCES collections(id) ON DELETE SET NULL,
  request_name TEXT NOT NULL,
  target_domain TEXT NOT NULL,
  url TEXT NOT NULL,
  method TEXT NOT NULL,
  status_code INTEGER NOT NULL,
  response_time INTEGER NOT NULL,     -- milidetik
  response_body TEXT NOT NULL,
  executed_at DATETIME NOT NULL
)

captured_variables (
  id INTEGER PRIMARY KEY,
  run_id INTEGER NOT NULL REFERENCES history_runs(id) ON DELETE CASCADE,
  domain_scope TEXT NOT NULL,
  var_name TEXT NOT NULL,
  var_value TEXT NOT NULL
)

Index idx_history_runs_executed_at mempercepat pengurutan berdasarkan waktu. Skema dibuat otomatis dengan CREATE TABLE IF NOT EXISTS; tidak ada migrasi versi.

Retensi History tidak dipangkas otomatis. Layar History memuat maksimal 500 run terbaru, tetapi database dapat terus bertambah. Hapus run lama secara manual jika diperlukan.

Diff Viewer (A vs B)#

Diff Viewer membandingkan body response dari dua eksekusi request yang sama. Ini berguna untuk melihat perubahan API setelah deploy atau memastikan perubahan request tidak menimbulkan regresi.

A · baseline

Response dari run sebelumnya. Ditampilkan di kiri dan ditandai -.

B · terbaru

Response dari run paling baru. Ditampilkan di kanan dan ditandai +.

Cara membuka

  • Tekan Ctrl+D saat sidebar tidak fokus dan Anda tidak berada di layar History.
  • Di sidebar, Ctrl+D berarti menghapus request; di History berarti menghapus run.

Sumber baseline

  1. TermAPI mencari history dengan method + URL yang sama dengan request aktif. URL di-resolve dengan environment/session variables agar cocok dengan URL yang benar-benar dikirim.
  2. Jika ditemukan, dua run terbaru dipakai: run terbaru sebagai B, run sebelumnya sebagai A.
  3. Jika tidak ada, dipakai dua run terakhir global, dengan catatan sumber di layar diff.
  4. Jika history belum ada, sisi B memakai response aktif dan sisi A memakai placeholder.

Memilih baseline manual

  • Tekan b untuk membuka daftar hingga 50 run terakhir untuk request tersebut.
  • ↑/↓ memilih, Enter menerapkan sebagai A. b/Esc membatalkan.
  • Tanda ✓ menunjukkan baseline yang sedang dipakai; ▸ menunjukkan kursor pemilihan.

Batch runner & chaining#

Batch runner menjalankan semua request pada folder collection (dan subfolder sesuai kedalaman) lalu menampilkan hasilnya dalam tabel.

Menjalankan batch

  1. Fokuskan sidebar (Tab) dan pilih folder collection.
  2. Tekan Ctrl+L.
  3. Atur konfigurasi:
    • ←/→ — kedalaman subfolder (0 = folder ini saja; default = seluruh subtree).
    • c — toggle mode Paralel ↔ Chaining.
    • r — jumlah auto retry 0–3.
    • Enter — jalankan; Esc — batal.

Mode paralel

  • Semua request dikirim bersamaan sebagai sekumpulan command Bubble Tea.
  • Request diurutkan berdasarkan path relatif sebelum dijalankan.
  • Setiap hasil disimpan ke history saat selesai.
  • Tidak ada jaminan urutan eksekusi; cocok untuk request independen.

Mode chaining

  • Request dijalankan berurutan sesuai urutan path.
  • Setelah response sukses (2xx/3xx), JSON scalar diekstrak menjadi variabel.
  • Variabel diterapkan ke {{KEY}} pada URL, params, headers, cookies, body, file, dan auth request berikutnya.
  • Variabel juga masuk ke session variables.
  • Jika masih ada template yang belum ter-resolve, request tersebut gagal dengan error unresolved chained variable {{...}}.

Layar hasil

TombolAksi
↑/↓ atau j/kPilih request
Tab/Shift+TabGanti tab response
EscKembali ke editor
KlikBerinteraksi dengan panel response

Kolom tabel: status, nama request, waktu, dan jumlah attempt. Warna status mengikuti 2xx/4xx/5xx dan error.

Retry batch Retry batch berlaku untuk semua method (berbeda dari retry manual yang hanya untuk method idempoten) dan dipicu oleh error transport sementara, status 408, 429, atau 5xx.

Wire inspector (WebSocket & gRPC)#

Ctrl+W membuka Wire Inspector. URL awal diambil dari URL request aktif.

  • Protocol WebSocket dipakai untuk URL ws://, wss://, atau default.
  • Protocol gRPC dipilih jika URL berawalan grpc:// atau mengandung :50051.
  • Koneksi WebSocket memakai header kosong dan ping loop otomatis. gRPC memakai kredensial insecure.

Layout

  • Header — throughput (TP), RTT, dan status koneksi.
  • Event stream — TX, RX, CTRL, ERR dengan waktu relatif/absolut, ukuran, status, dan payload ringkas.
  • Inspector — detail event terpilih (buka/tutup dengan i).
  • Composer — kirim pesan dengan Ctrl+Enter.
  • Status bar — petunjuk dan status export.

Format request lengkap#

Contoh berikut memakai format terstruktur modern. TermAPI masih menerima format legacy dan menormalkannya saat dimuat.

JSON + query + path parameter

id: update-user
name: Update user
method: PUT
url: "{{BASE_URL}}/users/{user_id}"
params_list:
  - key: user_id
    value: "{{user_id}}"
  - key: dry_run
    value: "false"
headers_list:
  - key: Accept
    value: application/json
body_spec:
  type: json
  raw: |
    {
      "name": "Ada",
      "active": true
    }
auth:
  type: bearer
  token: "{{token}}"

Form URL encoded

body_spec:
  type: form
  fields:
    - key: username
      value: admin
    - key: password
      value: "{{password}}"

Multipart dengan file

body_spec:
  type: multipart
  fields:
    - key: avatar
      value: ./assets/avatar.png
      kind: file
    - key: caption
      value: profile picture
      kind: text

Binary

body_spec:
  type: binary
  file: ./payload.bin
  content_type: application/octet-stream

API key di query

auth:
  type: api_key
  key: api_key
  value: "{{API_KEY}}"
  add_to: query

Legacy

id: list-users
name: List users
method: GET
url: https://api.example.com/users
headers:
  Accept: application/json
body: ""

Saat disimpan, TermAPI menulis ulang field terstruktur dan mengosongkan field legacy.

FAQ#

Apakah diff membandingkan request lama dengan request baru?

Tidak. Yang dibandingkan adalah body response. A adalah response dari run sebelumnya, B adalah response dari run terbaru. Definisi request (URL, header, body) tidak di-diff.

Bagaimana membandingkan response yang sudah lama, setelah banyak request lain?

Buka Diff Viewer dari request tersebut (Ctrl+D), lalu tekan b dan pilih run lama sebagai baseline. Selama run tersebut masih ada di history, ia bisa dipilih. Filter otomatis menggunakan method + URL, sehingga request lain tidak menggeser baseline.

Apakah data saya dikirim ke cloud?

Tidak. Semua collection, environment, history, dan export disimpan lokal. Tidak ada telemetry atau akun.

Apakah secret terenkripsi?

Tidak. File YAML dan SQLite menyimpan teks biasa. Gunakan izin filesystem yang ketat dan jangan commit secret.

Bisakah memakai beberapa environment sekaligus?

Tidak. Hanya satu environment aktif. Session variables dapat menimpa nilai environment untuk key tertentu.

Apakah bisa dijalankan di Windows?

Kode Go dan Bubble Tea bersifat lintas platform, tetapi proyek ini memakai SQLite CGO. Build di Windows memerlukan toolchain C yang kompatibel. Repositori belum menyertakan panduan atau CI khusus Windows.

Kenapa Ctrl+D kadang menghapus, kadang membuka diff?

Perilakunya kontekstual: di sidebar ia menghapus request; di History ia menghapus run; di layar utama dengan sidebar tidak fokus ia membuka Diff Viewer.

Kenapa ada request yang tidak di-retry?

Retry manual hanya untuk method idempoten (GET, HEAD, OPTIONS, PUT, DELETE) agar POST/PATCH tidak terkirim ganda. Batch runner dapat me-retry semua method sesuai konfigurasi.

Apakah response yang error masuk history?

Ya. Run yang gagal disimpan dengan status code 0 dan pesan error sebagai body. Ini memungkinkan investigasi dan diff kegagalan.

Bagaimana cara update dokumentasi ini?

Edit docs/index.html, docs/assets/styles.css, atau docs/assets/app.js. Tidak ada proses build; cukup refresh browser. Tambahkan id section dan link sidebar jika menambah bagian baru.
